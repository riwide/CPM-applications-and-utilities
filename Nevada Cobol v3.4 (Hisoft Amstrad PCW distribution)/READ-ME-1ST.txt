1) The Nevada Cobol v3.4 contains additional language features which are not described in the manual, and are described in the readme within the Hisoft (Amstrad PCW) distribution.

2) Be cautious of the editor you are using - the Cobol source cannot compile when containing embedded tab characters.

3) The compiler (CC.COM) when run with no command tail will give the following:

======================================
CC       COM
NEVADA COBOL (C) COPYRIGHT 1979, 1985
ELLIS COMPUTING, INC.
REV 3.4 (22 OCT 85) COMPILING
        CBL 95 FILE CANNOT BE FOUND 

CC SOURCE.SOW L'<CR>
  WHERE THE FILE EXTENT CONTAINS
  THE OPTIONAL DRIVE ASSIGNMENTS
  NOT THE (CBL) FILE TYPE! 

S=SOURCE CODE DRIVE
O=OBJECT CODE DRIVE
W=WORK DRIVE
L=LIST PROGRAM TO SCREEN
' USE APOSTROPHE ON LITERALS

PLEASE CHECK AND TRY AGAIN!!! 

======================================

The above is often misunderstood as an error that file "CBL.95" is missing. This is not so.

The compiler will use the three character file type of a file name on the command line as selection for drive letters associated with the compilation. When no file name is given it seems that the compiler is erroneously searching for a file ".CBL" and when this is not found it gives the error code "95" and message "File Not Found".

Solution: Just invoke the compiler with the file name that you wish to compile, without the extension, e.g. to compile RENUMBER.CBL just do "CC RENUMBER<CR>"
